# 校园食评 · Campus Food Review

> 一个面向大学生的校园美食测评移动端网站。同学自己上传吃过的美食（店名 / 菜名 / 标签 / 星级 / 图文），经管理员审核后公开；按「店名 + 菜名」自动聚合计算平均分与好评率，形成校园好味道榜单。

**在线体验**：https://campus-food-review-75704.app.workbuddy.host/?sharecode=ZLBWUGVFN6
（手机、电脑均可访问）

---

## 一、项目定位

- **只做测评，不做交易**：没有下单、支付、购物车，专注「商家 + 菜品」维度的真实评价。
- **内容来自用户**：不预置任何菜品数据，所有美食由同学上传实拍图 + 评分 + 文字产生。
- **先审后发**：用户提交后状态为「待审核」，只有管理员通过才会公开展示，可驳回违规内容。
- **数据驱动榜单**：按「店名 + 菜名」聚合同名美食，4~5 星计为好评，自动计算平均分与好评率并排序。

适用场景：校园内小范围使用 + 求职作品集案例。

## 二、功能清单

| 角色 | 功能 |
|---|---|
| 同学（用户） | 浏览首页统计 / 热门标签 / 好评榜单；按标签筛选、搜索、按评分 / 评价数 / 最新排序；查看菜品详情与全部公开测评；上传美食（店名选填、菜名必填、星级、文字、最多 3 张实拍图、匿名开关）；图片自动压缩 |
| 管理员 | 密码登录；按待审核 / 已通过 / 已驳回 / 全部筛选投稿；通过 / 驳回（可填原因）；一键切换状态；CSV / JSON 导出全部数据；在线修改管理密码 |

页面路由（哈希路由，无后端框架）：

| 路由 | 页面 |
|---|---|
| `#/home` | 首页：统计卡、热门标签、好评榜、最近上传 |
| `#/dishes` | 美食列表：标签筛选、搜索、排序、美食卡片 |
| `#/food/:key` | 美食详情：评分面板 + 逐条图文测评 + 去测评入口 |
| `#/upload` | 上传页：表单 + 图片上传 + 匿名开关 |
| `#/admin` | 管理后台：登录 + 审核 + 导出 + 改密码 |

## 三、技术架构

```
浏览器（原生 HTML / CSS / JavaScript，手机优先响应式）
   │
   ├─ 哈希路由（hashchange）驱动页面渲染
   ├─ Canvas 图片压缩 → base64 存云数据库
   └─ WorkBuddy Cloud SDK（BaaS）───┐
                                    ├─ 云数据库（PostgreSQL）
                                    │    ├─ 行级安全 RLS
                                    │    └─ SECURITY DEFINER 数据库函数
                                    └─ 鉴权 / 存储服务（平台托管）
```

- **前端**：原生三件套，无构建步骤、无第三方 UI 框架；CSS 变量统一配色，媒体查询适配手机 / 平板 / 桌面。
- **视觉**：日系动漫美食插画风，奶油黄 / 番茄红 / 海苔绿食物色系，CSS 纸张纹理 + 手绘感圆角边框 + 柔和多层阴影；无复杂动画，保证低端机稳定。
- **后端**：采用 BaaS 云开发（云数据库 + 数据库安全函数），无需自建服务器；前端通过公开 Key 直连，权限由数据库 RLS 保证。
- **SDK**：`@tencent-ai/workbuddy-cloud-sdk`，已内置到 `vendor/`，不依赖 CDN，离线也能加载页面逻辑。

## 四、数据库设计

### `food_posts`（美食投稿表，核心）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigint 主键 | 投稿 ID |
| `shop_name` | text | 店名 / 摊位名（选填，空则显示"未注明店名"） |
| `dish_name` | text | 菜品名称（必填，1~60 字） |
| `tags` | text | 标签，逗号分隔，最多 6 个 |
| `rating` | smallint | 星级 1~5 |
| `content` | text | 测评正文，5~1000 字 |
| `images` | text[] | 实拍图（压缩后的 dataURL），最多 3 张 |
| `is_anonymous` | boolean | 是否匿名 |
| `nickname` | text | 昵称（匿名时为"匿名用户"） |
| `status` | text | `pending` / `approved` / `rejected` |
| `reject_reason` | text | 驳回原因 |
| `created_at` / `reviewed_at` | timestamptz | 提交 / 审核时间 |

### `admin_config`（管理员配置表）

| 字段 | 说明 |
|---|---|
| `id` | 固定为 1 |
| `passcode_hash` | 管理密码的 MD5 值 |
| `updated_at` | 最近修改时间 |

### 行级安全（RLS）

- 公开读：匿名用户只能 `SELECT` 状态为 `approved` 的投稿 —— **待审核 / 已驳回内容对外不可见**。
- 受限写：匿名用户只能 `INSERT` 状态固定为 `pending` 的记录，且评分、字数、店名菜名长度均通过约束校验 —— **无法直接写入"已通过"内容**。
- 管理员操作通过 `SECURITY DEFINER` 函数封装，函数内部校验密码 hash，绕过 RLS 完成审核 / 导出。

主要函数：`admin_check`（校验密码）、`admin_list_posts`（列出全部投稿）、`admin_set_post_status`（改状态）、`admin_export_posts`（导出 JSON）、`admin_change_passcode`（改密码）。

## 五、核心逻辑说明

1. **先审后发**：用户 `insert` 只能写 `pending`；由于 RLS 只读 `approved`，提交后**不回读新行**（直接展示成功页），避免触发权限错误。管理员通过后，公开列表立即出现该条。
2. **评分聚合**：前端把已通过投稿按 `店名|菜名` 分组，`平均分 = Σ星级 / 条数`，`好评率 = 4~5 星条数 / 总条数 × 100%`；榜单按平均分降序，同分按评价数、最新时间排序。每条投稿仍作为独立测评卡片展示。
3. **图片处理**：`< 8MB` 的 JPG / PNG / WEBP，用 Canvas 等比缩放到最长边 1100px 后以 JPEG 0.7 质量转 dataURL 存储，控制体积；最多 3 张。
4. **数据导出**：管理员调用 `admin_export_posts` 获取全量数据（含待审核 / 已驳回），前端拼接为带 BOM 的 CSV（Excel 直接打开不乱码）或格式化 JSON。
